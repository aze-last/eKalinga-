## Getting Started

This manual is written for operators and administrators using the desktop application in **Local mode**. It focuses on the modules available in the current build: **Dashboard**, **Validated Beneficiaries**, **Aid Request**, **Budget**, **Distribution**, **Cash-for-Work**, and **Settings**.

Before you begin, confirm that the workstation can open the application and reach the configured local database preset.

| Requirement | Notes |
| :--- | :--- |
| **Application mode** | Use the `Local` preset for routine on-site workstations. |
| **Database access** | The local MySQL or MariaDB-compatible database must be reachable from the workstation. |
| **Account type** | Use an admin or authorized operator account issued by the barangay or system owner. |
| **Protected actions** | Sensitive settings may require current-password confirmation and, in some workflows, additional verification. |

### Key Operational Rules:
* Use the **left navigation** to move between operational modules.
* Use **search, filters, and summary cards** at the top of each page to narrow large record sets quickly.
* Use **Settings** only when you are assigned administrative responsibility for the workstation or data source.
* If the selected database has no admin account yet, the app switches to **Initial Admin Setup**. Create the first admin account there, then return to normal sign-in.
* For standard onsite workstations, keep the active preset on `Local`. Use `Network (LAN)` only when the workstation must point to an available LAN server. `Local` and `Remote` are fixed by the shipped app configuration, while `Network (LAN)` is the only editable preset before sign-in.
* If you change `Network (LAN)` details, use **Test Connection**, then click **Save and Continue** to return to the login screen.
* On the login screen, open **Connection Settings** only if you need to change the active app database before sign-in.

### Installation and First-Time Setup

Use this section when preparing a new workstation or reinstalling the desktop application.

#### Step 1: Install the Application
1. Run the current installer package provided by your administrator or release source. The shipped installer file follows the pattern `eKalingaPlus-Setup-<version>.exe` (e.g., `eKalingaPlus-Setup-1.0.6.exe`).
2. Double-click the installer file: `eKalingaPlus-Setup-1.0.6.exe`.
3. Follow the installation wizard.
4. Choose installation folder (default: `C:\Program Files\eKalinga+\AttendanceShiftingManagement.exe`).
5. Click **Next** to start installation.
6. Wait for installation to complete and click **Finish**.

#### Step 2: Launch the Application
* Double-click the **SmallMunicipal** / **eKalinga+** icon on your desktop  
* **OR** go to **Start Menu** $\rightarrow$ **eKalinga+** $\rightarrow$ **Launch Application**.

#### Step 3: First-Time Login
* **Username:** `admin@barangay.local`
* **Password:** `admin123`
* Click **Login**

> **Note:** The application comes with a pre-configured database. No additional setup is needed!

## Dashboard Overview

The **Dashboard** is the main landing page for operators. It surfaces the primary workflow areas as large navigation cards so staff can move directly to the module they need.

### Modules Accessible via Dashboard:
* **ASSISTANCE RECORDS** / **AID REQUEST:** Search particular beneficiary for claims and records.
* **MASTERLIST / VALIDATED BENEFICIARIES:** Review validated beneficiary records and lists.
* **BUDGET:** Monitor allocations, balances, and release usage.
* **DISTRIBUTION:** Manage release flow and beneficiary distribution.
* **CASH-FOR-WORK:** Track attendance, events, and payout processing.
* **REPORTS:** Generate exports and operational report outputs.
* **GGMS TRANSACTIONS:** View and filter all eKalinga+ transactions synced to GGMS.
* **SEMINAR ATTENDANCE:** Create seminars and capture scan-based attendance.
* **SETTINGS:** System configuration and security administration.

### Operational Guidance:
* Use Dashboard for quick entry into Validated Beneficiaries, Aid Request, Budget, Distribution, Cash-for-Work, Reports, and Settings.
* Use it as the standard starting point at the beginning of each shift.
* Return here when handing over the workstation so the next operator can navigate cleanly.

## Masterlist and Registry

The **Masterlist Registry** (and **Validated Beneficiaries**) module is used to review and monitor beneficiary records that are ready for operational processing. This page is typically used before requests are finalized or before distribution activities are prepared.

### Workflow Steps:
1. Open **Validated Beneficiaries** or **Masterlist** from the dashboard or left navigation.
2. Use the search and filters (`Search registry...`) to locate a beneficiary record or batch.
3. Review total counts:
   * **Total Registered** (e.g., 40,561)
   * **Civil Registry Linked**
   * **PWD Count**
   * **Senior Citizens**
4. Review the status and supporting details (Beneficiary ID, Address, Demographics, Status) before moving the record to the next operational step.
5. Use the available actions (e.g., **Scan via PC Camera**, **Upload Photo**) to confirm or return items according to your office process.

## Budget Management

The **Budget** module tracks available funds and organizes budget records by program. Use the dashboard view for totals and current status, then switch to Program Setup when you need to define or adjust the budget structure.

### Features & Layout:
* **GGMS Allocation**, **Private Donations**, **Combined Available** (General Use & Locked/Earmarked), and **Total Released**.
* **Spent This Week** and **Spent This Month** tracking.
* **Budget Browser:** Allows searching budget codes/names, filtering by category, and performing project creation.

---

### Program Setup

**Program Setup** (e.g., *Create New Project - Waterfall*) is where administrators maintain the program list and related budget definitions that feed the operational pages and adding of beneficiaries.

#### Fields and Controls:
* **Basic Information:** Project Name, Project Code, Project Distribution type, Description.
* **Release Settings:** Distribution Type (Cash / Goods), Max Payout Amount (PHP).
* **Duration & Cap:** Start Date, End Date, Hard Budget Cap (Optional).
* **Funding Source:** Select source, Donor Name, Donation Amount (PHP), Date, Reference Number / Receipt #, Proof File Path, Remarks.
* **Enroll Beneficiaries (Optional):** Add specific beneficiaries to the project.

## Distribution Workflow

The **Distribution** module supports planning and releasing assistance to approved beneficiaries. The main page shows distribution records, while the distribution panel is used for the detailed handoff workflow.

### Workflow Steps:
1. Open **Distribution** and locate the correct record, batch, or activity by entering/browsing the **Project Code**.
2. Review the distribution status overview divided into:
   * **RELEASED / CLAIMED**
   * **PENDING**
   * **UNRELEASED / UNCLAIMED**
3. Use **Swipe ID Card / Search ID** or select a beneficiary from the list.
4. Open the **Beneficiaries Profile Form** to verify details:
   * **Household Relationship** and **Beneficiary Profile**.
   * **Requirements Checklist** (e.g., *Cedula / Community Tax Certificate*, *Barangay Certificate*).
5. Take appropriate action:
   * **CONFIRM RELEASE:** Process payout when all requirements are met.
   * **MARK AS PENDING:** If requirements are missing (requires entering a reason, e.g., *"Lacking: Cedula"*).
   * **DECLINE:** Deny payout if ineligible.
6. Save or confirm the transaction before moving to the next beneficiary.

* **Create Event**

### Workflow:
1. Use this page after a Cash-for-Work event or cycle has been prepared.
2. Review attendance and participant records before generating any output tied to the event.
3. If the page is empty, confirm that the correct event and preset are selected.

## Settings and Administration

**Settings** centralizes workstation and administrative tools. Use this area carefully because it includes system identity, account maintenance, protected data-source settings, and recovery tools.

### Available Sub-Sections:
* **System Profile:** Controls workstation identity, login presentation, serial number, and light/dark theme.
* **My Account:** Manage signed-in user account details.
* **Security:** Manage security levels and passwords.
* **Remote Snapshot:** Configure remote database credentials, test connections, and import pending rows.
* **Database Backup:** Create backups and manage database recovery.
* **App Database:** Manage local/network server settings and connection strings.
* **GGMS Budget Source:** Configure integration with GGMS.

> 🔒 **Protected Settings Prompt:** Sensitive sections (Remote Snapshot, App Database, GGMS Budget Source) do not open immediately. The system protects them behind a current-password prompt (`Protected settings: Re-enter the current admin password`) before allowing changes.

## Backup and Restore

Use **Database Backup** to create full, incremental, or differential backups for the currently selected app preset. Restore uses the selected restore point and automatically resolves the required backup chain.

### How to Perform Backup / Restore:
1. Open **Settings** and select **Database Backup**.
2. Confirm that the **Active Backup Preset** shown at the top of the page is correct (e.g., `Local: 127.0.0.1:3306 / attendance_shifting_db`).
3. Action buttons available:
   * **CREATE FULL BACKUP:** Create a baseline full backup. *(Must be done first before incremental or differential backups).*
   * **CREATE INCREMENTAL BACKUP:** Compares against the latest incremental chain for the latest full backup.
   * **CREATE DIFFERENTIAL BACKUP:** Compares against the latest full backup only.
   * **RESTORE BACKUP:** Restore database from a selected restore point.
4. Use Restore Backup only after confirming the correct restore point and chain.

## Troubleshooting

Use the table below for the most common operator-side issues before escalating to the system administrator or developer.

| Issue | Action |
| :--- | :--- |
| **Login fails** | Verify the username, password, and active preset. If the issue persists, request an account reset from the administrator. |
| **No data appears on a page** | Check filters, selected period, and current preset. Refresh the page or reopen the module. |
| **Protected settings stay locked** | Re-enter the current admin password. If verification is required, complete the assigned security step before retrying. |
| **Incremental or differential backup is unavailable** | Create a full backup first for the active preset, then return to the backup page. |
| **Local preset is incorrect** | Open the protected App Database settings only if you are the assigned administrator. Do not guess or overwrite connection values. |
